
# Record Package Guide

## Overview
DBのレコードを表現するパッケージ。  
特にmodelとDBのテーブルモデル、SQLモデルと差分がある場合に用意する。modelへの変換ロジックも持つ。  

modelとstructのフィールドが一致する場合はrecordは不要になるので、その場合はmodelにrecordの実装を含める形をとる。  
それらの判断基準についても、後述する。  

## 資料
`docs/draft`配下の対応する集約のドキュメントを参照。  
Model定義の集約ルートに対してrecordを用意することが多い。  

## 実装基準
modelで実装が完結する場合はrecordは不要となる。その判断基準を以下に示す。  

以下の場合にrecordパッケージを用意する
- modelとDBのテーブルモデル、SQLモデルに差分がある場合
- 独自型のスキャン処理が必要な場合。ただしGoの場合はsqlパッケージのScannerインターフェースで可能になるので考慮不要

上記以外の場合は、recordを用意しない。  
開発初期においては、基本的にテーブルモデルとmodelは一致するはずであるので、用意しない。  
開発が進み、テーブルとmodelでのモデリングが乖離してきた場合に用意するもの。  

## 実装
構造体を含め、実装する関数や定数は、同じファイルに定義する。  
詳細は以下。  

### 構造体
DBレコードを表現する構造体を定義する。  
SQLのselect句の結果を格納するため、その結果のカラム名を、フィールドの`db`タグで指定する。  

model packageでrecordの機能を含める場合は、modelの構造体はDBのテーブルと一致しているはずで、そのままDBマッピングに使用する。  

また、構造体のリストを持つ構造体も定義する。命名は`<構造体名>List`とする。  
これは、DBレコードは常にリストを返すが、そのリストごとmodelに変換するためのメソッドを定義するため。  

### DB マッピング定義
`gorp`の`DbMap`にテーブルを登録する関数を定義する。  
関数は`gorp.DbMap`を引数にとり、その中で`AddTableWithName`を呼び出して構造体がどのテーブルと紐づくか定義する。  
また、`SetKeys`でprimary keyも定義する。基本的にIdはアプリケーションで採番するので、auto incrementは不要。  

### Keys関数
`pkg/database/model#Keyed`型を満たすようにKeys関数を定義する。  
構造体のキーの値を`[]interface{}`に詰めて返す関数。  
gorpの主キーでレコードを取得するGet関数に渡す引数となるので、主キーの値を返す形。  

### 定数
テーブル名とエイリアスを定義する  

### SELECT句定義
同じselect句を何度も利用する場合には、select句とfrom句を合わせて定義しておく。  
その際`goqu`を使用する。  
構造体のフィールドを満たすようにselect句を定義する。逆説的にselect句を満たすように構想体が定義される。  

### 変換メソッド
modelにrecordの機能を実装するのなら不要なもの。  
record構造体をmodel構造体に変換するメソッドを定義する。  
命名は`Transfer`とする。また、リストを変換するメソッドも定義する。命名は`TransferList`。  
構造体をレシーバにとるメソッドなので命名は統一でよい。

内部の実装は、modelのコンストラクタ関数を呼び出して、model構造体を生成する。  
modelのコンストラクタ関数の中には、他の集約の構造体を引数にとることもあるが、それは変換関数の引数に受ける形にする。  

recordは、sqlの結果なのでフラットな構造になっているが、modelは階層構造になっているので、そのように変換する。  
また、left joinの結果はオプショナルになるので、nilチェックしてから変換する。  

リストを変換するメソッドは、構造体の変換関数を呼び出す形になる。
