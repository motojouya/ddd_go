
# Entry Package Guide

## Overview
システムへの入力を表現するパッケージ。Webからの入力JSON情報を持ち、coreへの変換ロジックを持つ。  
入力情報はcore構造体と異なることが多いので、常に用意する。  

## 資料
`docs/draft`配下の対応する集約のドキュメントを参照。  
特にModelのクラス図に定義すべき項目が記載されている。  
クラス図の読み方、凡例については、[docs/guideline/design.md](docs/guideline/design.md)を参照。  

## 実装
一つの構造体につき、一つのファイルを用意する。  
構造体を含め、実装する関数やインターフェースは、同じファイルに定義する。

### 構造体
入力データを表現する構造体を定義する。  
Echoフレームワークのバインディングタグを使用する:
- URLパラメータ: `param` タグ
- クエリパラメータ: `query` タグ
- JSONボディ: `json` タグ

draftドキュメント上のclass図で同じclassに定義され、実際にcoreでも利用される値であっても、Entryにおいては別の構造体に切り出すものもある。  
これは更新のタイミングが分かれるためで、その項目が単独で更新されるため、Entryが別の構造体になる。  
class図の凡例では`l`となっているので注意。  

### Transferable インターフェース
`pkg/database/core`にTransferableインタフェースが定義されている。  
ものによって、IdやNumを持つcoreの構造体や、リストで扱う構造体もあるので、それぞれにあったTransferableインタフェースを実装する。  

機能としては、entry構造体をcoreに変換する。変換の際にcoreのコンストラクタ関数や更新関数を呼び出す形。  
定義する変換関数は、次項を参照。  

Transaferableの種類は以下  
- Transferable  
  通常のもの  
- TransferableWithId  
  対応するcoreの構造体がidを持つとき、coreの新規作成時に呼び出す  
- TransferableWithIdAndNumber  
  対応するcoreの構造体がidとnumを持つとき、coreの新規作成時に呼び出す  
- TransferableList  
  集約に対して有限のリスト構造として保持される構造体をリストごと更新するためのもの  

また複数のTransferableを実装することもある。  

### Transferメソッド
entry構造体をcore構造体に変換する関数。  
Transferableインターフェースを実装する形で、構造体のメソッドとして定義する。  

内部的に、core構造体のコンストラクタ関数や更新関数を呼び出し、entryの構造体のフィールドを引数に渡す。  
coreの関数は、引数に他の集約の構造体をとることも多いが、それらは変換関数の引数で`Depend`が定義されているので、そこに詰めて受け取る。  
返り値は、集約ルートと変換したcore構造体。  

### リスト型構造体
集約ルートにリストとして保持される構造体の場合、entryにおいてもリストでわたってくることを想定する。  
そのため、対象の構造体のリストをフィールドに持つ構造体を定義する。  
そのリストにもタグにて、echoのバインディングタグを定義する。

命名は、`<構造体名>List`とする。  
リスト型構造体については、TransferableはTransferableListインタフェースを実装する。  

### TransferListメソッド
リスト型構造体に対して、定義するメソッド。  
Transferと違うのは、リスト型入力データと既存データに対して、削除、更新、新規で分けてそれぞれ計算する点。  
結果も、削除対象、更新対象、新規追加対象の3つに分類して返す。  

`pkg/basic/core`にIntersect関数が定義されているので、それを利用して実装する。  
既存データと入力データのうち、対応するもの、しないものを分けて、それぞれ削除、更新、新規追加の対象とする。  
basic.Intersectに渡すMatch関数については、次項を参照。  

更新対象のものは、既存データに対して、coreの更新関数を呼び出して更新する。  
新規のものは、coreのコンストラクタ関数を呼び出して変換する。  
それぞれ、別の集約の構造体を引数にとることもあるので、TransferListメソッドの引数`Depend`につめて受け取る。この時に複数の値になる場合は、スライスを詰めることもある。  
返り値は、集約ルートと、削除対象、更新対象、新規追加対象の3つのスライスを`pkg/database/core#MutationList`につめたもの。  

また、basic.Intesect関数は内部でループを回し、途中停止できない。  
非常に長いリストである場合は、パフォーマンスに影響が出る可能性があるため、事前にリストの上限値を超えていないか、バリデーションする。  

### Match関数
Intersect関数の中で、basic.Intersect関数に渡す、既存データと入力データのどの要素が対応するかを判定するための関数。  
既存データはcore、入力データはentryの構造体だが、基本的に何らかのIdを持っていることが多いので、そのIdを比較する傾向。  

命名は、`Match<構造体名>`とする。basic.Intersectの叙述関数となるため、その型に従う。  

### GetNumber 関数
numや、あるいは`XxxNum`という名前のフィールドを持つ構造体に定義するメソッド。  
`basic.NumberGetter` インターフェースを実装する。  
エンティティのキーとなる番号を返す。
特にdraftドキュメントのModelのclass図上で、`l`という設定になっているものは特に用意する。  

#### Equal系関数
`basic.Find` などの述語関数として使用する比較関数。  
特にTranferメソッドの内部で仕様する。  
構想体の内部に別の構造体を持つ場合、多くは引数にリストを引き受けるため、どの構造体であるかを探す必要がある。  
その際に、`basic.Find`関数を使用する。
