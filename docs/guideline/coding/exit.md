
# Exit Package Guide

## Overview
システムからの出力を表現するパッケージ。entryと対になる存在。  
対になる存在だが、実装する関数はまるで違うので注意。  
その集約のcoreの値以外にも、任意の項目であったり他の集約の構造体をもつこともある。  
coreから自分自身への変換ロジックを持つ。  

## 資料
`docs/draft`配下の対応する集約のドキュメントを参照。  
特にModelのクラス図に定義すべき項目が記載されている。

## 実装
一つの構造体につき、一つのファイルを用意する。  
構造体を含め、実装する関数は、同じファイルに定義する。

### 構造体
出力データを表現する構造体を定義する。  
JSONタグで出力フィールド名を指定する。  

構造体としてはフィールドに持ちつつも、出力には含めない項目は`json:"-"`タグを使用する。  
空の場合にJSONから省略したいフィールドには`omitempty`を指定する。

### 変換関数
core構造体をexit構造体に変換する関数。  
entryをcoreに変換する関数と違い、メソッドではなく、通常の関数として定義する。  
命名は`From<構造体名>`とする。引数にcore構造体を受け取り、exit構造体を返す。  

また、集約ルートとなるcoreに対して実装された変換関数は、内部に保持するフィールドの構造体を変換する変換関数を再帰的に呼び出す。  
構造体をリストで保持している場合は、リスト用の変換関数も用意する。  
リストの変換関数の場合は`From<構造体名>List`と命名する。  

### Relate関数
exit構造体のフィールドは、別の集約のexitの構造体を持つこともある。  
それらを後から紐づけるための関数。`pkg/basic/core`のRelate,RelateUnique関数に渡す叙述関数となる。  
命名は`Relate<関連データの構造体名>`とする。引数に自分自身の構造体と、関連データの構造体を受け取る。  

紐づけ対象の場合は、紐づけた自分自身の構造体を返し、紐づけ対象でない場合は、変更せずに自分自身の構造体を返す。  
また、紐付けが成功したかどうかのbool値も返す。

紐づけ対象か否かは、基本的にIdのフィールドがあるので、それで判断する傾向。
